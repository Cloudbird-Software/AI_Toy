# ADR-0012 T14 M2 LLM 真推理：Qwen3-0.6B GGUF + 自研最小 llama.cpp dlopen 绑定（v0.3.0 ABI）
状态：accepted 2026-09-03（issue #133 推进线，M2-prep 分支 feat/t14-m2-llm）
背景：LLMEngine 为 M1 桩（NewQwen3LLM 固定串），VAD/ASR 已接真 ONNX 推理（PR #148，yalue/onnxruntime_go + libonnxruntime.so.1.29.0 惯例）。任务给定为 Qwen3-0.6B Q4_K_M GGUF（Apache 2.0，sha256 9acfc1e0…，已在台账/manifest）。需决策：Go 侧 llama.cpp 路线的绑定方式与库供给面（本机与 CI 均无现成 llama.cpp，无 cmake 预装）。
决策：
1. **推理后端 = llama.cpp，版本钉 v0.3.0**（commit c1d0e7a004015f23bc0233470b747b596f29b264）：GGUF 任务指定；该版本含 qwen3 arch 支持、C API 稳定（llama_init_from_model / llama_memory_clear 命名代）。MIT 已在台账。源码 cmake 编译（Release / CPU / BUILD_SHARED_LIBS=ON，GGML_NATIVE 默认开），产物 libllama.so.0.3.0 + libggml{,-base,-cpu}.so.0.22.0 安装 /usr/local/lib（与 libonnxruntime.so.1.29.0 同址惯例）+ ldconfig。
2. **绑定 = 自研最小 cgo dlopen 层（llm_lib.go），不用第三方绑定库**：与 yalue/onnxruntime_go 同构——运行时 dlopen（env T14_LLM_LIB 覆盖，默认版本化文件名），构建期零库依赖，无库机器 go build 照常、测试 Skip（基础设施面惯例）。第三方绑定（go-skynet/go-llama.cpp 等）vendor 旧版 llama.cpp（不识别 qwen3 arch）或要求 cmake 进构建链，属更大基建变更。零新增 Go module 依赖（license 台账零膨胀）。**ABI 破坏面**：llama_model_params / llama_context_params / llama_batch 逐字段复刻 include/llama.h v0.3.0，结构体按值传递全部留在 C shim 内；跨版本换库必须换版本化文件名 libllama.so.<ver> 并回归本包测试，默认路径不匹配即降级桩（不静默错跑）。v0.3.0 实测语义锚：get_logits_ith 入参为批内 token 下标（output_ids 映射行），显式 pos 数组不依赖 batch_get_one 位置推断。
3. **生成口径（PoC）**：Qwen3 ChatML 非思考模板（assistant 起始前置空 <think> 块抑制思考链，输出端 stripThink 兜底）+ 系统人设「小云雀」（与 runtime-fsm 口径一致）；贪心解码（argmax，确定性可回归），温度/top-p 面留路径选项；单轮生成、每调用 llama_memory_clear（不跨调用续写）；默认 n_ctx=512 / maxNew=128 / threads=4（env T14_LLM_CTX / T14_LLM_MAX_TOKENS / T14_LLM_THREADS 覆盖）。
4. **接口与降级不变**：LLMEngine 签名不动；模型/库缺失或初始化失败 → M1 桩 fallback（qwen3LLMStub 固定串），Err()/InFallback() 暴露原因，Skip 惯例照 T3/T14。log 静音（no-op 回调，T14_LLM_VERBOSE=1 排障）。
备选否决：纯 Go GGUF 推理库（Go 生态无生产级 qwen3 arch 全图实现——Q4_K_M dequant/RoPE/GQA/KV cache 全自研超出 PoC 范围，且引入未成熟依赖的维护面）；go-llama.cpp 类 cgo 绑定（见决策 2）；llama-server 子进程 + 纯 Go HTTP 客户端（零 cgo 但引入进程生命周期管理面：启动/健康检查/端口/超时，嵌入式运行时多进程拆分留作未来选项，非 M2 需要）；sherpa-onnx 通道（无通用 GGUF LLM 推理面）；换 ONNX 格式走 ORT GenAI（任务指定 GGUF，换格式属新导出链）。
后果：实测（4 核 7.4G，nice -19）：生成吞吐 P50≈29.5 / P95≈31.0 tok/s（threads=4；threads=2 生成 P50≈28.8 带宽受限、prompt 处理 2× 变慢）；TTFT（prompt 解码墙钟口径，51 tok）≈0.35s；进程 RSS ≈869MB（权重 C 堆为主）。go.mod 零新增；ledger llama.cpp 条目补 ABI 注记（模型/依赖均已在案，无新条目）；inference 包首次直接持有 cgo 代码（此前 cgo 由 onnxruntime_go 间接引入，工具链面无新增要求）；CI 无库无模型环境全 Skip 保持绿。延迟预算影响（LLM 一句 ≈0.7~1.0s 墙钟）并入 latency-report LLM 段，与 ASR 段缺口同案升级 founder 划拨，不动 configs/budgets。
