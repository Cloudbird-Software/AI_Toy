# ADR-0013 T14 ASR 换型流式：sherpa-onnx streaming zipformer 双语 int8 + ORT Go 直驱
状态：accepted 2026-09-03（M2-T14-ASR 换型 PoC，issue #133 推进；founder 已决策「换流式模型」，本 ADR 记录具体选型与落地口径。注：原编号 ADR-0012 已被 T14 LLM PR 占用，本 ADR 重编号为 ADR-0013）
背景：T14 话轮级 ASR 当前为 FireRedASR2-AED int8 非流式整句识别（PR #148，与 T3 同 ORT Go 装配）。实测 RTF≈0.84~1.0（4 核 CPU），5s 话轮墙钟 4.3~5.1s，须等「尾静音→定稿」后整句解码，远超话轮级 2s 体验线（reports/eval/T14/latency-report.md 2026-09-03 节）。founder 决策换流式模型；本 ADR 落地选型、驱动方式与接口换型口径。
决策：
1. **模型选 sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20（Apache-2.0）**：k2-fsa 官方导出档（基座 pfluo/k2fsa-zipformer-chinese-english-mixed，icefall pruned_transducer_stateless7_streaming 训练），中英双语、可商用、license 链条干净（HF 仓库 license 标签 + 基座仓库核验）。int8 encoder（181.9MB）+ fp32 decoder（13.9MB）+ int8 joiner（3.2MB）。weights 落盘 /root/workspace/datasets/models/streaming-zipformer-zh-en-2023-02-20/（manifest t14-streaming-zipformer.yaml，license 台账已登记），不入 git。
2. **驱动方式 = ORT Go 直驱（yalue/onnxruntime_go，与 FireRedASR2/T3 vap 同装配惯例），否决 sherpa-onnx CGo 运行时路线**：仓库已有单一 ORT 绑定纪律（ort.go「不引入第二个 ORT 绑定库」）；sherpa-onnx CGo 引入整棵 C++ 依赖树（license 台账/审计面膨胀 + 交叉编译负担），而流式 zipformer 的推理面小且闭合：encoder 固定块 + transducer 贪心（joiner 逐位置 argmax、decoder 滑窗 [y₀,y₁]→[y₁,tok]），Go 直驱 ≈300 行。块语义经 Python ORT 原型实证后固化：encoder 元数据 T=39 / decode_chunk_len=32，即首块 39 新帧、后续每块 = 上块尾 7 帧（输入 4:1 下采样左上下文）+ 32 新帧 → 8 个下采样位置；分层缓存（cached_{len,avg,key,val,val2,conv1,2}×5 栈）以 new_* 输出整组接管回喂，初始零值形状按 ONNX 声明构造。1.wav Go 全链输出与 Python 原型、FireRed 非流式 golden 三方逐字一致。
3. **接口换型签名不变：StreamingZipformer 实现 ASREngine（Recognize([]byte)(string,error)），FireRedASR2 保留为备选实现**（engine.go 注释更新为双实现口径）。流式路径（FeedChunk 增量出部分文本 + Finish 定稿）与整句 Recognize 完全同代码路径——PoC 实测口径即可上线口径。端点检测仍归消费方（VAD hangover，T14-M2 已有 Silero VAD 真推理），Finish 只做尾帧零填充定稿刷新。
4. **量纲口径是两代模型的最大陷阱，已在代码注释钉死**：FireRedASR2 训练口径为 int16 量纲波形 fbank + 全局 CMVN；本流式模型为 icefall 归一化波形（[-1,1]）裸 log-mel、无 CMVN。两者 log-mel 相差 2·ln32768≈20.7 的常数偏移——错喂量纲时 encoder 输出形状正常但缓存数值 3~4 倍畸变、转写全空（无报错，纯静默失败，本次实测踩坑并经逐元素特征对拍定位）。pcm16ToUnitDomain 与 pcm16ToInt16Domain 并存，注释互指。
5. **实测结论（本机 4 核 7.4G，nice -n 19，intra-op=2，10 次 P50/P95，1.wav 5.10s）**：RTF P50=0.121 / P95=0.149（尽速喂入口径）；首字延迟（实时节奏墙钟）P50=1350ms / P95=1376ms；定稿延迟（endpointing 后 Finish 刷新）P50=26ms / P95=30ms。**验收线如实达成：话轮级定稿延迟 ≤2s ✓、RTF ≤0.5 ✓**。首字延迟的下限是模型块缓冲（首块 390ms 起、首个非 blank 出现于第 4 块 ≈1.35s），计算占比 <50ms——进一步压首字须换更小首块导出档或双语小模型（14M 档），当前不追求。intra-op=4 反而 RTF 升至 0.250（小块推理线程争抢），维持默认 2 线程。
备选否决：sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23（更快但中英混辨识力不足，儿童教学场景需英文词面）；SenseVoice-small / FireRedASR2（均非流式，不解决定稿等待）；whisper-streaming（重、许可与端侧预算不合）；sherpa-onnx CGo 运行时（见决策 2）；FireRedASR2S 流式 LLM 通道（无现成 ONNX 导出，训练面超出 M2 范围）。
后果：T14 话轮交互从「整句等待」转「边说边出字」；ASR 段延迟缺口消除（定稿 26ms ≪ 2s 预算），configs/budgets/latency.yaml 的 ASR 段划拨仍留 founder 决策（本 PoC 不改阈值面）。已知取舍：流式模型对重口音条目转写与 FireRed 有差异（3-sichuan「自己/纸巾」级），正式换型前建议以 T2 数据飞轮真实儿童语音做一次 WER 对比（两模型口径，M2 收口项）；int8 joiner 的 logit 带 3 维量化尾巴（6257 vs tokens 6254），argmax 限扫词表、越界按 blank 终结（joinArgmax 注释）。模型/库缺失降级桩惯例不变。
